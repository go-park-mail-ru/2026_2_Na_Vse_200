# Разработка

Техническая инструкция по запуску и настройке сервиса. Контракт API — в [docs/api.md](../docs/api.md).

## Запуск

Нужен только Go версии из `go.mod`.

```
go run ./cmd/server
```

Сервер поднимается на http://localhost:8080. Проверка:

```
curl http://localhost:8080/health      # {"status":"ok"}
```

Остановка — Ctrl+C: сервер дожидается текущих запросов и только потом завершается.

## Конфигурация

Всё читается из переменных окружения, значения по умолчанию рассчитаны на локальный запуск —
настраивать ничего не нужно.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_ADDR` | `:8080` | адрес, который слушает сервер |
| `APP_ALLOWED_ORIGIN` | пусто | адрес фронтенда для CORS; пусто — фронт и API на одном origin |
| `APP_COOKIE_SECURE` | `false` | флаг `Secure` у сессионной cookie; на стенде с HTTPS — `true` |
| `APP_SESSION_TTL` | `24h` | срок жизни сессии |
| `APP_SHUTDOWN_TIMEOUT` | `10s` | сколько ждём завершения запросов при остановке |
| `POSTGRES_DSN` | пусто | строка подключения к PostgreSQL |

Заданный `APP_ALLOWED_ORIGIN` требует `APP_COOKIE_SECURE=true`, иначе сервер не запустится:
при разных адресах сессионная cookie уходит с `SameSite=None`, а такую браузер без `Secure`
молча выбрасывает. На localhost `Secure` работает и поверх http.

Пример запуска с фронтендом на соседнем порту:

```
APP_ALLOWED_ORIGIN=http://localhost:3000 APP_COOKIE_SECURE=true go run ./cmd/server
```

### Секреты

Секретов в репозитории нет и быть не должно. В `.env.example` только имена переменных
и плейсхолдеры; реальные значения живут локально в `.env` (он в `.gitignore`), на стенде —
в переменных окружения сервера, а для сборки и деплоя их место в GitHub Secrets.

### Скрипт запуска

Чтобы не выставлять переменные руками в каждом терминале, есть `scripts/run.sh`:
он подхватывает их из `.env` и запускает команду.

```
cp .env.example .env                   # один раз, дальше правите под себя
./scripts/run.sh                       # сервер с настройками из .env
./scripts/run.sh go test ./...         # любая другая команда с теми же настройками
ENV_FILE=.env.stand ./scripts/run.sh   # взять другой файл настроек
```

Если `.env` нет, скрипт об этом скажет и запустит сервис на значениях по умолчанию.
На Windows скрипт запускается из Git Bash.

## Структура

```
cmd/server/                точка входа: конфигурация, логгер, обвязка, запуск
internal/apimessage/       коды ошибок и тексты для пользователя
internal/auth/             хеширование и проверка паролей
internal/config/           настройки из переменных окружения
internal/handlers/         HTTP-обработчики
internal/middleware/       обвязка: request_id, recover, логирование, CORS, JSON-ошибки
internal/models/           доменные сущности
internal/repository/       интерфейсы доступа к данным и ошибки хранилища
internal/repository/memory/  реализация в памяти процесса
pkg/response/              запись JSON-ответов
pkg/validation/            проверки данных от клиента
```
