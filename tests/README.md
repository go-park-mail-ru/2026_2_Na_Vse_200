# Тесты

Требование РК1 — покрытие не ниже 50%.

Файлы `*_test.go` лежат рядом с кодом. Тест может быть в том же пакете или
во внешнем пакете с суффиксом `_test`. Здесь — сводка и команды запуска.

## Покрытие

Фиксированная цифра быстро устаревает после добавления тестов и пакетов.
Для РК2 требуется общее покрытие **больше 60%** без сгенерированных моков:

```powershell
go test ./... '-coverprofile=cover.out'
Get-Content cover.out | Where-Object { $_ -notmatch '/mocks/|/mock_[^/]*\.go:' } | Set-Content -Encoding ascii cover.nomocks.out
go tool cover '-func=cover.nomocks.out'
```

Это исключает только код, созданный `mockgen`; непокрытые рабочие пакеты остаются
в расчёте. Профили покрытия игнорируются Git.

## Моки для HTTP-тестов

Используется `go.uber.org/mock v0.6.0`. Из корня репозитория повторить генерацию
после изменения интерфейсов:

```powershell
go run go.uber.org/mock/mockgen@v0.6.0 '-source=internal/repository/repository.go' '-destination=internal/repository/mocks/mock_repository.go' '-package=mocks'
go run go.uber.org/mock/mockgen@v0.6.0 '-source=internal/auth/password.go' '-destination=internal/auth/mocks/mock_hasher.go' '-package=mocks'
```

Сгенерированные файлы не редактировать вручную. `home_gomock_test.go` задаёт
ожидаемые вызовы каталога и проверяет JSON, а также остановку обработки при
ошибке. `auth_gomock_test.go` проверяет передачу хеша в хранилище, создание
сессии после регистрации и отсутствие сессии при неверном пароле. Тесты
продолжают проверять HTTP-поведение через `httptest`; моки заменяют только
зависимости обработчиков.

`cmd/server/main.go` юнит-тестами не покрывается: проверка потребовала бы занять
порт и отправить процессу сигнал. Закрывается прогоном на стенде.

## Что проверяется

### `internal/handlers`

Запросы идут через `httptest.NewRequest` и `httptest.NewRecorder`, без поднятия
сервера. Хранилища — реализации в памяти; для проверки отказов подставляются
подменные, возвращающие ошибку.

Регистрация:

- успех — `201`, сессионная cookie;
- занятый email — `409`;
- битый JSON и пустое тело — `400`;
- невалидные поля — `400` с разбором по полям;
- email в другом регистре — тот же аккаунт;
- в ответе нет ни пароля, ни хеша;
- идентификатор из выданной cookie находится в хранилище сессий и указывает
  на того же пользователя;
- недоступное хранилище сессий — `500`, аккаунт при этом создан.

Вход:

- успех — `200` и новая cookie;
- неверный пароль и неизвестный email дают побайтово одинаковый ответ;
- правила состава пароля не применяются;
- недоступное хранилище сессий — `500`.

Сессия:

- полный цикл: регистрация → `/me` → выход → `/me` с той же cookie даёт `401`;
- четыре причины отказа `/me` дают одинаковый ответ: нет cookie, сессия
  неизвестна, сессия истекла, пользователь удалён;
- выход без cookie и повторный выход — `204`;
- недоступное хранилище — `500`, а не `401`;
- при заданном `AllowedOrigin` cookie уходит с `SameSite=None` и `Secure`.

Главная:

- успех — `200`, `Content-Type`, три непустых массива;
- карточка трека содержит идентификатор, название, положительную длительность
  и хотя бы одного исполнителя;
- пустой каталог отдаёт `[]`, а не `null`;
- недоступное хранилище каталога — `500` без технических подробностей;
- `POST` — `405`;
- дата релиза приводится к UTC, неизвестная приходит как `null`;
- аватар приходит строкой или `null`.

Маршрутизация: неизвестный путь — `404` в JSON, чужой метод — `405`
с сохранённым заголовком `Allow`.

### `internal/repository/memory`

- создание проставляет идентификатор и дату;
- поиск по идентификатору и по email;
- повтор email — `ErrEmailTaken`;
- пятьдесят горутин с одним email — ровно одна успешная регистрация;
- отменённый контекст прерывает операцию;
- неизвестная сессия — `ErrSessionNotFound`;
- просроченная — `ErrSessionExpired`, запись при этом удаляется;
- удаление несуществующей сессии ошибкой не считается;
- предел выдачи каталога: ноль и отрицательное дают пустой список, значение
  больше длины отдаёт всё.

### `pkg/validation`

Табличные тесты на email, пароль и имя: граничные длины, отсутствие `@`, точка
на краю домена, пароль без цифры, слишком короткий и слишком длинный.

Отдельно:

- минимальная длина пароля считается в символах, максимальная в байтах;
- пробелы по краям пароля обрезаются одинаково при регистрации и входе;
- проверки возвращают объявленные причины отказа, различимые через `errors.Is`.

### `internal/auth`

- пароль проходит проверку после хеширования;
- два хеша одного пароля различаются;
- пароль длиннее 72 байт — `ErrPasswordTooLong`;
- испорченный хеш не принимается и даёт ошибку: пустая строка, обычный текст,
  обрезанный хеш, хеш другой схемы;
- два вызова генератора идентификатора сессии дают разные значения;
- хешер с ценой по умолчанию работает. Этот тест один на пакет: на боевой цене
  хеш считается около ста миллисекунд, остальные берут `MinCost`.

### `internal/middleware`

- паника даёт `500` в формате контракта, текст паники клиенту не уходит,
  стек и идентификатор запроса попадают в лог;
- CORS: разрешённый origin получает заголовки, посторонний — нет,
  `Allow-Origin` не равен звёздочке;
- идентификатор запроса переиспользуется, если это валидный UUID, иначе
  генерируется новый;
- чтение идентификатора из пустого контекста даёт пустую строку;
- обработчик, написавший тело без явного кода состояния, логируется как `200`;
- текстовые `404` и `405` от маршрутизатора подменяются на JSON;
- порядок обёрток в `Chain`.

### `internal/config`

Значения по умолчанию; чтение из окружения; неразбираемое значение роняет старт;
`APP_ALLOWED_ORIGIN` без `APP_COOKIE_SECURE=true` — ошибка конфигурации.

### `internal/models`

`IsExpired` до срока, ровно в срок и после.

### `pkg/response`

Код состояния, `Content-Type`, формат ошибки с разбором по полям и без него.

## Запуск

```
go test ./...                 прогон
go test ./... -cover          покрытие по пакетам
go test ./... -v              с именами тестов
```

Общую цифру для РК2 считайте по профилю без сгенерированных моков,
как показано в разделе «Покрытие» выше. Для просмотра функций и HTML-отчёта:

```powershell
go tool cover '-func=cover.nomocks.out'
go tool cover '-html=cover.nomocks.out'
```

Отдельный пакет или тест:

```
go test ./internal/handlers/ -cover
go test ./internal/handlers/ -run TestSessionLifecycle -v
```

`cover.out` в `.gitignore`.
