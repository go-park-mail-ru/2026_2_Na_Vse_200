# Тесты

Требование РК1 — покрытие не ниже 50%.

Файлы `*_test.go` лежат рядом с проверяемым кодом. Здесь — описание проверок и команды запуска.

## Покрытие

Покрытие измеряется по текущему коду командами из раздела [«Запуск»](#запуск).
Фиксированная цифра в документации быстро устаревает после добавления пакетов.
В `internal/repository/postgres/session_repo_test.go` есть интеграционные тесты сессий:
они запускаются только при заданном `TEST_POSTGRES_DSN`. Без этой переменной они пропускаются.
У `cmd/server` и `cmd/migrate` пока нет собственных тестовых файлов. Тесты обработчиков
используют локальные неэкспортируемые подмены из `internal/handlers/repositories_test.go`;
они собираются только при тестировании. Работающий сервер использует PostgreSQL.

## Что проверяется

### `internal/handlers`

Запросы идут через `httptest.NewRequest` и `httptest.NewRecorder`, без поднятия
сервера и подключения к БД. Неэкспортируемые подмены репозиториев объявлены в
`repositories_test.go` этого пакета; для проверки отказов используются подмены,
возвращающие ошибку. Эти вспомогательные реализации не входят в сборку сервера.

Регистрация:

- успех — `201`, сессионная cookie;
- занятый email — `409`;
- битый JSON и пустое тело — `400`;
- невалидные поля — `400` с разбором по полям;
- email в другом регистре — тот же аккаунт;
- в ответе нет ни пароля, ни хеша;
- идентификатор из выданной cookie находится в хранилище сессий и указывает
  на того же пользователя;
- недоступное хранилище сессий — `500`, аккаунт при этом создан.

Вход:

- успех — `200` и новая cookie;
- неверный пароль и неизвестный email дают побайтово одинаковый ответ;
- правила состава пароля не применяются;
- недоступное хранилище сессий — `500`.

Сессия:

- полный цикл: регистрация → `/me` → выход → `/me` с той же cookie даёт `401`;
- четыре причины отказа `/me` дают одинаковый ответ: нет cookie, сессия
  неизвестна, сессия истекла, пользователь удалён;
- выход без cookie и повторный выход — `204`;
- недоступное хранилище — `500`, а не `401`;
- при заданном `AllowedOrigin` и `CookieSecure=true` cookie уходит с `SameSite=None` и `Secure`.

Главная:

- успех — `200`, `Content-Type`, три непустых массива;
- карточка трека содержит идентификатор, название, положительную длительность
  и хотя бы одного исполнителя;
- пустой каталог отдаёт `[]`, а не `null`;
- недоступное хранилище каталога — `500` без технических подробностей;
- `POST` — `405`;
- дата релиза приводится к UTC, неизвестная приходит как `null`;
- аватар приходит строкой или `null`.

Маршрутизация: неизвестный путь — `404` в JSON, чужой метод — `405`
с сохранённым заголовком `Allow`.

### `internal/repository/postgres`

`session_repo_test.go` проверяет работу с настоящим PostgreSQL:

- сохранение сессии и чтение через независимый пул соединений;
- отказ для неизвестных или некорректных идентификаторов и истёкших сессий;
- отзыв сессии при выходе и повторное удаление;
- пакетную очистку истёкших записей с сохранением действующих;
- отказ при повторе идентификатора без перезаписи исходной сессии;
- внешний ключ на аккаунт и каскадное удаление его сессий;
- отмену контекста и отличие ошибки БД от ошибки авторизации.

Проверки используют отдельную схему внутри выделенной тестовой базы; схема создаётся
для теста и удаляется после него. Действующая сессия хранится в БД, а не в экземпляре
репозитория, поэтому повторное создание репозитория не теряет её.

Для запуска нужен `TEST_POSTGRES_DSN`, указывающий на отдельную тестовую базу.
Пользователю БД нужны права создавать и удалять схемы и объекты внутри неё.
Рабочую базу приложения для этих тестов не используйте. `POSTGRES_DSN` для запуска API
и `TEST_POSTGRES_DSN` для тестов задаются независимо.

### `db/migrations`

`local_storage_test.go` проверяет миграцию `000005_media_local_storage` на настоящем
PostgreSQL. Тесты включаются через `TEST_POSTGRES_DSN` и создают отдельную случайную
схему для каждой проверки; существующие схемы не меняются. SQL применяется на одном
соединении, а ошибка миграции откатывается на этом же соединении.

- Старые `(bucket, object_key)` преобразуются в `storage_key` с сохранением namespace:
  одинаковые имена в разных bucket не конфликтуют.
- Сохраняются идентификаторы, метаданные файлов, временные отметки и внешние ключи.
- Проверяются уникальность ключа, запрет абсолютных путей, обхода через `.`/`..`,
  пустых компонентов, обратных слешей, двоеточий и управляющих символов.
- Обычные пробелы и Unicode в именах допустимы.
- Полный `up/down/up` сохраняет исходные legacy-значения без обрезки пробелов.
- Некорректные старые пути отклоняют `up` целиком; несовместимые с прежней моделью
  новые ключи отклоняют `down` целиком. После отказа схема и данные остаются прежними.

### `pkg/validation`

Табличные тесты на email, пароль и имя: граничные длины, отсутствие `@`, точка
на краю домена, пароль без цифры, слишком короткий и слишком длинный.

Отдельно:

- минимальная длина пароля считается в символах, максимальная в байтах;
- пробелы по краям пароля обрезаются одинаково при регистрации и входе;
- проверки возвращают объявленные причины отказа, различимые через `errors.Is`.

### `internal/auth`

- пароль проходит проверку после хеширования;
- два хеша одного пароля различаются;
- пароль длиннее 72 байт — `ErrPasswordTooLong`;
- испорченный хеш не принимается и даёт ошибку: пустая строка, обычный текст,
  обрезанный хеш, хеш другой схемы;
- два вызова генератора идентификатора сессии дают разные значения;
- хешер с ценой по умолчанию работает. Этот тест один на пакет: на боевой цене
  хеш считается около ста миллисекунд, остальные берут `MinCost`.

### `internal/middleware`

- паника даёт `500` в формате контракта, текст паники клиенту не уходит,
  стек и идентификатор запроса попадают в лог;
- CORS: разрешённый origin получает заголовки, посторонний — нет,
  `Allow-Origin` не равен звёздочке;
- идентификатор запроса переиспользуется, если это валидный UUID, иначе
  генерируется новый;
- чтение идентификатора из пустого контекста даёт пустую строку;
- обработчик, написавший тело без явного кода состояния, логируется как `200`;
- текстовые `404` и `405` от маршрутизатора подменяются на JSON;
- порядок обёрток в `Chain`.

### `internal/config`

Значения по умолчанию; чтение из окружения; ошибки разбора bool и длительности;
локальный HTTP допускает `APP_ALLOWED_ORIGIN` при `APP_COOKIE_SECURE=false`.

### `internal/models`

`IsExpired` до срока, ровно в срок и после.

### `pkg/response`

Код состояния, `Content-Type`, формат ошибки с разбором по полям и без него.

## Запуск

```
go test ./...                 прогон
go test ./... -cover          покрытие по пакетам
go test ./... -v              с именами тестов
```

Интеграционные проверки сессий и SQL-миграций с PostgreSQL
(после создания отдельной базы `music_test`):

```powershell
$env:TEST_POSTGRES_DSN = 'postgres://postgres:YOUR_PASSWORD@localhost:5432/music_test?sslmode=disable'
go test ./internal/repository/postgres ./db/migrations -count=1 -v
```

```bash
TEST_POSTGRES_DSN='postgres://postgres:YOUR_PASSWORD@localhost:5432/music_test?sslmode=disable' \
  go test ./internal/repository/postgres ./db/migrations -count=1 -v
```

Незаданный `TEST_POSTGRES_DSN` означает пропуск интеграционных проверок, а не подтверждение
работоспособности PostgreSQL. Общие команды `go test ./...` также включают эти проверки,
если переменная задана.

Общая цифра и разбор по функциям:

```
go test ./... -coverprofile=cover.out
go tool cover -func=cover.out
go tool cover -html=cover.out
```

Отдельный пакет или тест:

```
go test ./internal/handlers/ -cover
go test ./internal/handlers/ -run TestSessionLifecycle -v
```

`cover.out` в `.gitignore`.
